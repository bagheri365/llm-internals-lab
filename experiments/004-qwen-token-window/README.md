# Experiment 004 — Token-window causal analysis

Test which **cached decoding steps** are sufficient to change Qwen3-4B's claimed developer. Layer 24, neuron 386, dose −98, four prompts, six modes = **24 generations**.

```bash
python experiments/004-qwen-token-window/run.py
```

Outputs: `results/experiment-004-token-window.json` and `.csv`. The JSON records exact edited decode steps and hook call counts for each generation.

| Mode | Cached decoding steps edited |
|---|---|
| `none` | None (baseline) |
| `first1` | 1 only |
| `first5` | 1–5 |
| `first10` | 1–10 |
| `after10` | 11 onward |
| `all` | Every cached decoding step |

**Important:** Step 1 is the cached forward pass that *processes the first generated token to predict the second*. The first generated token itself is predicted by the unmodified prefill pass. All modes leave prefill unmodified. The hook distinguishes prefill from decode using sequence length under `use_cache=True`, and verifies one prefill and either N−1 or N cached decoding passes for N returned tokens (some Transformers versions perform an extra final pass). The `extra_final_forward` field flags the latter; edits on that final pass do not affect returned text. If generation ends early, some windows may not be reached; consult `edited_steps`.

The outputs are claims generated by a model, not evidence of its true developer. This experiment does not measure token probabilities or isolate a single semantic feature. Use `--revision <full-commit-sha>` to pin weights for reproducibility; otherwise `model_commit` may be null.
